# 决策：改用独立桌宠应用

日期：2026-05-19

## 背景

初始方向是生成 Codex 兼容宠物，并尝试把原生宠物显示尺寸从 `192x208` 放大到约三倍。过程中尝试过修改 Codex 相关安装资源和脚本。

## 问题

这个方向暴露了几个根本问题：

- Codex 原生宠物显示尺寸受 Codex 应用内部实现限制，不是只替换素材就能稳定改变。
- 修改 `Codex.app` 安装包会触发签名、更新和 Electron 启动稳定性风险。
- 曾出现 Codex 应用疯狂退出重启和崩溃报告，说明 patch 安装包不是可靠交付方式。
- 用户希望宠物可以提示 Codex 任务状态，后续也可能支持 Claude 等工具；这种联动需求更适合独立进程实现。

## 决策

放弃 patch `Codex.app`，改为独立 macOS companion app：

- 使用 Swift/AppKit 实现透明悬浮窗。
- 独立安装到 `~/.codex/pet-companion/CodexPetCompanion.app`。
- 通过本地进程和状态文件推断 Codex 活动状态。
- 保留 Codex 标准宠物包作为 fallback，但主运行帧使用高清 PNG。

## 结果

这个方案带来的收益：

- 不再影响 Codex 主应用稳定性。
- 显示尺寸可以由 companion app 自己控制。
- 动作策略、拖动体验和状态提示都可以独立迭代。
- 后续支持其他工具时，只需新增状态读取层，不需要改第三方应用安装包。

代价：

- 需要单独安装和启动 `CodexPetCompanion.app`。
- 当前只支持 macOS arm64 预编译包。
- 状态联动是基于本地文件修改时间的启发式判断，不是 Codex 官方 API。

## 后续约束

- 不再把 patch `Codex.app` 作为主线方案。
- 如果确实需要和 Codex 更深集成，应优先寻找官方扩展点或外部状态接口。
- 桌宠运行逻辑必须和 Codex 主应用解耦，崩溃或退出时不能影响 Codex 使用。
