# 脸部表情暂停与后续 TODO

## 背景

动作体系已经有 `PetExpression`、表情动作 catalog、表情调度和表情 clip 名称，但当前脸部视觉表达仍不完整。曾尝试在整帧 PNG 上按固定坐标绘制眨眼、视线、微笑和眉眼变化，这个方向暂停，不进入主线交付。

## 判断

固定坐标整帧绘制不适合作为正式脸部表情方案。

原因：

- 它把脸部结构、眼镜、头发遮挡和当前正面素材强绑定，换姿态或换素材就容易错位。
- 直接在整帧上画肤色 patch、眼线和嘴形，会产生“贴上去”的感觉，和原始美术不一致。
- 主动作发生头部偏转、身体位移或轮廓变化时，硬编码坐标无法稳定跟随。
- 如果把每个表情和每个主动作都烘焙成完整 clip，资产数量会爆炸，也不利于调度组合。

这个方案可以作为很早期的占位验证，但不应该作为桌宠动作体系的长期实现。

## 正确方向

脸部表情应该做成局部分层或局部贴图 overlay，而不是继续补整帧涂抹。

推荐路线：

1. 建立脸部局部坐标系：明确脸部 bbox、眼睛/眉毛/嘴巴/脸颊 anchor、适用姿态和缩放规则。
2. 拆分表情资产：眼睛、眉毛、嘴巴、脸颊分别做透明 PNG 或矢量层，和原始角色美术风格一致。
3. runtime 合成：基础姿态或主动作帧先渲染，再按 z-order 合成当前表情层。
4. 调度解耦：`currentExpression` 是状态，眨眼和视线是高频局部动作，主动作只在支持 overlay 的姿态上叠加表情。
5. 大动作兜底：完整转身、明显侧身、伸展等不稳定姿态暂时冻结表情，或者使用该动作专门绘制的真实关键帧。

## TODO

- 定义 expression asset contract：坐标系、anchor、z-order、mask、适用动作和禁用动作。
- 绘制真实表情素材：`neutral`、`focused`、`curious`、`happy`、`tired`、`error`，至少覆盖眼睛、眉毛和嘴部。
- 实现 `ExpressionRenderer`：把基础帧、主动作帧和局部表情层合成，避免修改原始整帧资产。
- 调整调度器：表情状态和 blink/eye-shift 微动作分开，主动作峰值期间按动作能力决定延后、冻结或叠加。
- 增加验证：生成表情 contact sheet 做人工验收，再用轻量像素/快照检查保证表情资产没有丢失。
- 更新验收标准：脸部表情未完成前，不能把“完整动作体系”描述为包含已完成的视觉表情层。

## 暂不做

- 不继续在整帧 PNG 上硬编码画眼睛、嘴巴或肤色 patch。
- 不把所有主动作和所有表情组合烘焙成完整 clip。
- 不在 runtime 引入 ML 插帧来解决脸部表情；脸部表情优先用语义关键帧和局部分层。
